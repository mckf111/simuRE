# ADR-0001: 使用 Web + Three.js + Vite 构建第一版游戏原型

- 状态：accepted
- 日期：2026-05-17
- 决策人：项目维护者 / Codex

## 背景

项目当前只有工程宪法骨架，没有业务技术栈、运行命令、验证命令或游戏源码。用户希望开始制作一个类似现代肩后视角生存动作体验的游戏原型，需要尽快得到可试玩成果，同时保持原创性和可维护性。

第一版目标是验证核心手感：肩后视角、移动、瞄准、射击、敌人压迫、弹药和生命资源，而不是直接进入完整商业级资产、动画和关卡管线。

## 决策

第一版采用浏览器 3D 原型路线：Vite 负责本地开发与构建，Three.js 负责 3D 渲染、摄像机、光照、材质和程序化几何体。源码放在 `src/`，入口为 `index.html`，最快可信验证为 `npm run build`。

运行时不引入后端、账号、遥测或网络调用。游戏资产全部使用程序化几何体和材质，避免使用 RE4/Capcom 或其他第三方版权素材。

## 备选方案

| 方案 | 优点 | 缺点 | 为什么没选 |
|---|---|---|---|
| Web + Three.js + Vite | 上手快、跨平台、浏览器即可试玩、适合验证手感 | 需要自行组织游戏循环、碰撞和状态 | 选定方案 |
| Unity | 成熟游戏工具链、生态完整、适合后续大型项目 | 当前 repo 未配置 Unity；初始工程和编辑器依赖更重 | 第一版原型速度不如 Web 轻量 |
| Unreal Engine | 高保真渲染和 3D 管线强 | 工程体积大、学习和构建成本高 | 当前目标是快速核心玩法验证 |
| Godot | 开源、游戏结构清晰 | 当前 repo 无 Godot 项目事实；浏览器即时试玩链路不如 Vite 直接 | 可作为后续重评选项 |

## 后果

### 正面

- 能在本仓库内快速建立可运行、可构建、可验证的游戏原型。
- 不需要额外安装大型游戏编辑器即可试玩。
- 程序化资产降低版权和素材管理风险。

### 负面（重要）

- 第一版不会具备完整 3A 动画、物理、AI 和关卡制作能力。
- 后续如果转向 Unity/Unreal/Godot，需要迁移游戏逻辑和资产组织。
- Three.js 不自带完整游戏框架，复杂系统需要逐步抽象。

## 失效条件

- 项目目标转为完整商业级 3D 游戏制作，需要动画蓝图、导航网格、复杂物理、关卡编辑器或资产管线。
- 浏览器性能无法支撑目标玩法或画面规模。
- 用户明确要求改用 Unity、Unreal、Godot 或其他引擎。
