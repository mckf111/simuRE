## 用户故事

作为玩家，我想在浏览器里试玩一个原创肩后视角生存动作原型，以便验证移动、瞄准、射击、敌人压迫和资源压力是否有游戏感。

## 验收标准（成功长什么样）

- [x] 运行 `npm run build` 能完成生产构建。
- [x] 运行 `npm run dev -- --host 127.0.0.1` 后，浏览器能看到 3D 场景、玩家角色、HUD 和开始界面。
- [x] 玩家可移动、转向、瞄准、射击、装填和闪避。
- [x] 敌人会逐波生成、追击玩家、近身造成伤害，并可被射击消灭。
- [x] HUD 能显示生命、体力、弹药、波次、威胁数量和分数。
- [x] 不使用 RE4/Capcom 的角色、剧情、关卡、商标、音效或美术资产。

## 范围

### In scope

- 浏览器内可玩的单人 3D 原型。
- 肩后视角摄像机、鼠标瞄准、键盘移动。
- 程序化场景、灯光、雾效、简易角色和敌人几何体。
- 敌人波次、弹药与补给掉落、死亡/重新开始流程。
- README、项目状态、架构、接口、ADR 和 CHANGELOG 更新。

### Out of scope（明确不做）

- 复刻 RE4 的角色、敌人、剧情、关卡、UI、音效或美术资产。
- 多人联机、账号、云存档、遥测、排行榜。
- 复杂动画状态机、电影化过场、任务系统、完整关卡编辑器。

## 设计

第一版是一个封闭圆形试炼场。玩家以肩后视角控制原创角色，在有限弹药和体力下抵御逐波逼近的敌人。场景资产全部由 Three.js 几何体和材质程序化创建，避免引入版权素材。

核心循环：

1. 点击开始后进入指针锁定。
2. 玩家移动、瞄准和射击。
3. 敌人从场地边缘分批生成并追击玩家。
4. 消灭敌人获得分数，少量掉落弹药或治疗补给。
5. 清完一波后进入下一波，敌人数量和速度提高。
6. 生命归零后显示重新开始入口。

## 技术任务（按顺序）

1. 建立 Vite + Three.js 运行入口 -> 验证：`npm install` 后能解析依赖。
2. 实现 3D 场景和肩后视角玩家控制 -> 验证：浏览器首屏非空，玩家可移动转向。
3. 实现射击、装填、闪避、敌人追击和伤害 -> 验证：可消灭敌人，生命和弹药变化。
4. 实现 HUD、波次、补给和死亡重开 -> 验证：UI 数值随游戏状态更新。
5. 更新长期文档 -> 验证：占位符不再描述业务事实缺失。

## 风险与权衡

- 使用 Web/Three.js 能最快得到可试玩原型，但不是高保真 3A 制作管线。
- 第一版以程序化几何体替代美术资产，能避免版权和素材管线成本，但视觉精细度有限。
- 没有引入物理引擎，碰撞和敌人行为保持简化；后续复杂关卡可能需要重评架构。

## 验证计划

- 单元测试：当前无测试框架，第一版不新增。
- 集成测试：`npm run build` 已通过。
- 手动验证 / 生成物检查：已启动本地开发服务器，用浏览器确认 3D 画面、HUD、开始流程、射击弹药变化、敌人波次和非黑屏渲染。

## 备注

本原型只借鉴肩后视角生存动作类型中的通用交互，不复刻具体商业游戏内容。
